# trace — 잘못된 답변의 원인 찾기

**답변만 보고 원인을 추측하지 않는다.** 이 저장소에서 "지난 주 박스오피스"가 1년 전 데이터를
답했을 때, 첫 추측은 "LLM이 오늘 날짜를 몰라서"였다. 실제로 찍어 보니 모델은 날짜를 알고 있었고,
**데이터가 없자 연도를 1년 낮춰 재호출**한 것이 원인이었다. 추측대로 고쳤다면 버그가 남았다.

## 1. 재현

```bash
.venv/Scripts/python scripts/trace.py "사용자가 한 질문 그대로"
```

- 실제 OpenAI·KOBIS·Tavily를 호출한다. 질문 하나에 보통 1~2센트.
- 서버와 같은 입력(오늘 날짜 SystemMessage + 질문)을 쓰고, 대화 DB는 건드리지 않는다.
- **LLM은 실행마다 달라진다.** 한 번에 재현되지 않으면 2~3번 돌려 본다. 같은 질문에
  `20260911`과 `20260914`가 번갈아 나온 적이 있다.

| 옵션 | 쓰임 |
|---|---|
| 질문 여러 개 | `trace.py "질문1" "질문2"` — 비슷한 질문과 비교 |
| `--date YYYY-MM-DD` | 오늘 날짜를 바꿔 재현. 프롬프트와 도구의 "집계 전 차단"이 같은 날짜를 본다. **단, KOBIS의 실제 데이터는 진짜 오늘 기준**이라 미래 날짜를 흉내 내면 빈 결과가 나온다 |
| `--full` | 도구 결과와 답변을 자르지 않고 전부 본다 |

## 2. 읽는 법

```
[LLM 1] 입력 1755 / 출력 25 토큰
[도구 1] kobis_search {'search_type': 'weekly', 'query': '20260912'}
         → 주간 박스오피스 (2026-09-07~2026-09-13) 1위. 오디세이 ...
[LLM 2] 입력 2110 / 출력 60 토큰
답변: ...
요약: LLM 2회 · 도구 1회 · 입력 3865 / 출력 85 토큰 · 5.4초
```

**도구 호출 인자를 먼저 본다.** 대부분의 원인은 답변 문장이 아니라 인자에 있다.

## 3. 원인 분류

| 증상 | 확인할 곳 | 이 저장소에서 있었던 예 |
|---|---|---|
| 도구를 안 부름 / 엉뚱한 도구 | `SYSTEM_PROMPT`의 `## 도구 선택 기준`, `## 답변 범위` | 영화 질문을 범위 밖으로 거절 |
| 도구는 맞는데 **인자**가 틀림 | 도구 설명, `KobisInput` 필드 설명 | 출연진 질문에 `detail` 대신 `movie` |
| 날짜·기간이 틀림 | 주입된 오늘 날짜, 프롬프트 날짜 규칙, `boxoffice_too_recent()` | 1년 전 데이터를 "지난 주"로 답함 |
| `[TOOL_ERROR ...]` 후 이상한 복구 | 그 코드에 대한 `## 도구 에러 처리` 지침, 에러 메시지의 힌트 | `NO_DATA` 후 연도를 낮춰 재호출 |
| 도구 결과는 맞는데 답변이 틀림 | 결과가 너무 길거나 후보가 섞였는지 (`--full`) | "기생충" 검색 1위가 "마약 기생충" → `pick_movie()` |
| 출처 칩이 없음 | `sources.extract_sources()`, 도구 결과 형식 | `response_format`을 되돌리면 쪽번호 출처가 사라짐 |
| 느리거나 비쌈 | 요약 줄의 LLM·도구 횟수와 토큰 | 도구 정의만 2,132토큰이던 것을 692로 줄임 |

KOBIS 응답 자체가 의심되면 LLM 없이 도구만 호출해 본다 (KOBIS는 무료):

```bash
.venv/Scripts/python -X utf8 -c "from agent import kobis_search; print(kobis_search.invoke({'search_type':'weekly','query':'20260912'}))"
```

## 4. 고친 뒤 — 재발 방지까지가 한 세트

1. **같은 `trace.py` 명령으로 다시 돌려** 고쳐졌는지 확인한다. 2~3번 돌려 흔들리지 않는지도 본다.
2. **판정 로직을 고쳤다면** `kobis_format.py`·`sources.py`의 순수 함수로 두고 `tests/unit/`에 테스트를 추가한다.
   docstring에 **어떤 실패를 막는지**(이번 증상)를 적는다.
3. **LLM 행동을 고쳤다면** `tests/evals/golden_dataset.json`에 이번 질문을 항목으로 추가한다.
   rubric에 "이런 답이면 실패(실제로 있었던 버그)"를 명시한다. 날짜에 따라 정답이 바뀌는 항목은
   특정 날짜를 적지 말고 "주어진 오늘 날짜의 직전 주"처럼 상대적으로 쓴다.
4. 관련 평가를 돌린다 (과금 — 관련 항목 `--ids`부터).
5. 커밋은 `release` 스킬 절차를 따른다.
