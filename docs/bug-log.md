## B-009
**레이트리밋이 방문자별이 아니라 프록시 주소별로 걸릴 수 있음** · 서버 · 미해결

- **증상**: 아직 신고·관측된 적은 없다. 코드를 읽다가 발견했다.
- **원인(추정)**: `server.py`의 `Limiter(key_func=get_remote_address)`는 TCP 연결 상대의 주소로 센다.
  브라우저는 백엔드에 직접 붙지 않고 `web/app/api/chat/route.ts`(Vercel, compose에서는 `web` 컨테이너)를
  거친다. `route.ts`는 원래 클라이언트 IP를 넘기지 않고, uvicorn도 `--proxy-headers` 없이 뜬다.
  그러면 모든 방문자가 몇 개 안 되는 프록시 주소를 함께 쓰게 되어, **전체 방문자 합계로 분당 10회**
  제한이 걸릴 수 있다.
- **확인 방법**: Railway 로그에서 `chat.request` 이벤트의 `client` 값이 요청마다 같은지 본다.
- **수정 방향**: `route.ts`가 `x-forwarded-for`를 넘기고, 백엔드는 신뢰하는 프록시에서 온 경우에만 그 헤더로
  센다. 헤더를 그냥 믿으면 누구나 값을 바꿔 제한을 피할 수 있다.

## B-008
**루트에 Dockerfile을 추가하자 Railway 배포 실패** · 배포 · 해결 (`cdd933e`, PR #3)

- **증상**: PR #2(Docker Compose) 병합 후 Railway 배포가 약 1분 만에 failure. 이전 버전이 계속 서비스돼
  `/health`는 200이었다. 사이트가 열린다고 새 버전이 배포된 것은 아니다.
- **원인**: 직전 커밋(문서 변경)의 배포는 성공했고, #2에서 Railway가 볼 수 있는 변화는 저장소 루트의
  `Dockerfile`·`.dockerignore`뿐이었다. Railway가 nixpacks 대신 루트 Dockerfile을 썼거나(비루트 사용자
  `app`이 root 소유 볼륨에 대화 DB를 못 씀), `.dockerignore`가 nixpacks 빌드에도 적용된 것으로 본다.
  빌드 로그를 직접 보지 못해 둘 중 어느 쪽인지는 확정하지 못했다.
- **수정**: `docker/api.Dockerfile`과 `docker/api.Dockerfile.dockerignore`(BuildKit의 Dockerfile별 제외 규칙)로
  옮기고, compose에서 `dockerfile:`로 지정했다. 병합 후 Railway 배포 성공을 확인했다.
- **재발 방지**: `rules/ci-deps.md`에 "저장소 루트에 Docker 파일을 두지 말 것"을 적었다. 배포 확인은
  `check_deploy.py`가 Railway 배포 상태까지 보므로 같은 일이 생기면 바로 드러난다.

## B-007
**한국어 문장이 글자 중간에서 줄바꿈** · 프론트 · 해결 (`192ee36`)

- **증상**: 빈 화면 설명 문장이 "함/께"처럼 단어 중간에서 끊겼다(리디자인 중 스크린샷으로 발견).
- **원인**: 브라우저 기본값(`word-break: normal`)은 한글을 글자 단위로 끊는다.
- **수정**: `globals.css`의 `body`에 `word-break: keep-all`(어절 단위)과 `overflow-wrap: anywhere`(긴 URL 대비).
- **재발 방지**: `web/AGENTS.md` 디자인 섹션에 적었다.

## B-006
**`kobis-005` 채점 점수가 통과선 근처에서 흔들림** · 평가 · 관찰 중

- **증상**: 전체 평가에서 `kobis-005`(주말 박스오피스)가 judge 2점으로 한 번 실패했다. 같은 날 다시 3번 돌리면
  5·4·4점이었고, 답변은 매번 같은 기간·같은 1위였다.
- **원인**: 답변 문제가 아니라 LLM 채점관의 판정 흔들림으로 본다. 채점관과 사람 판정의 일치도는 재지 않았다.
- **대처**: 이 항목만 혼자 떨어지면 먼저 다시 돌려 본다. `tests/evals/README.md`의 "알려진 흔들림"에 적었다.
- **남은 일**: 채점을 사람 판정과 맞춰 보거나, rubric을 더 구체적으로 써서 흔들림을 줄인다.

## B-005
**한국어 줄거리 질문을 한국어 그대로 검색해 못 찾음** · 검색 · 해결 (`48e1ff3`)

- **증상**: 제목을 모르는 한국어 줄거리 질문("요리하는 쥐")에서 정답(라따뚜이)을 못 찾거나 웹 검색으로 샜다.
- **원인**: 코퍼스가 영어인데 모델이 제목을 떠올리지 못하면 한국어 검색어를 그대로 넘겼다. 원문 기준
  한국어 제목 적중률은 0.30이었다.
- **수정**: `imdb_search` 설명에 "자료가 영어라 검색어는 영어로, 줄거리 묘사도 영어 키워드로"를 추가했다.
  실제 기준 Hit@8이 0.97 → 1.00이 됐고, 한국어 검색어는 2 → 0번으로 줄었다.
- **재발 방지**: `tests/evals/run_retrieval.py --actual`로 다시 잴 수 있다. CLAUDE.md 프롬프트 규칙에 적었다.
  하이브리드 검색(BM25)은 한국어 단어가 영어 문서에 없어 효과가 없다는 것도 측정으로 확인했다.

## B-004
**같은 대화에서 다시 물은 질문에 출처가 사라짐** · 에이전트 · 해결 (`4a99949`)

- **증상**: 배포 후 "쇼생크 탈출 감독이 누구야?"에 답은 맞는데 출처가 없다는 신고가 들어왔다.
- **원인**: 같은 대화에서 다시 물으면 모델이 이전 차례 결과를 기억해 도구 없이 답했다. 출처는 도구를 부른
  차례에만 붙는다. 평가는 항목마다 새 대화로 한 번만 물어서 이 상황을 검사하지 못했다.
- **수정**: `SYSTEM_PROMPT`에 "사실은 이전 대화에 있어도 매번 도구로 확인"을 추가했다(요약·인사·거절은 예외).
- **재발 방지**: 평가에 `history` 필드와 `multiturn-001` 항목을 추가했다. 프롬프트를 고치기 전에 이 항목이
  실패하는 것을 먼저 확인했다.

## B-003
**CSV에서 제목 숫자를 연도로 읽은 영화 2편** · 데이터 · 해결 (`495659c`)

- **증상**: '2001: A Space Odyssey'가 2001년, '1917'이 1917년으로 들어와 있었다. SQL로 연도를 거르면서
  "2001년 영화"에 1968년 영화가 나오는 식으로 답변에 드러날 수 있었다.
- **원인**: 원본 크롤러가 제목 앞 숫자를 연도로 읽었다.
- **수정**: 두 줄의 연도를 1968, 2019로 고쳤다.
- **재발 방지**: 단위 테스트가 두 편의 연도와 "제목 앞 4자리 숫자가 연도와 같은 행이 없는지"를 검사한다.

- **증상**: `SELECT title, cast FROM movies`가 syntax error.

## B-001
**잘린 PDF 때문에 정답이 코퍼스에 없었음** · 데이터 · 해결 (`ba7df7f`)

- **증상**: 평가가 15/15 통과하는데 RAG 원본에 IMDB 항목의 정답이 없었다. 'Shawshank'·'Darabont'가 0회였고,
  답변에는 PDF 쪽번호 출처가 붙어 거짓 인용이 됐다.
- **원인**: PDF가 표 칸 너비에서 글자를 잘라 그린 것이었다. 그려지기 전에 잘려 어떤 파서로도 복원되지 않는다.
  모델이 사전지식으로 답하고 키워드 검사가 통과시켰다.
- **수정**: 원본 CSV로 교체했다(영화 한 편 = 문서 한 개). 그러자 "평점 1위"가 틀렸는데, 벡터 검색이 정렬을 못
  하기 때문이라 정렬·집계용 `imdb_sql` 도구를 추가했다.
- **재발 방지**: `imdb_search` 평가 항목마다 `corpus_evidence`를 적고, 그 문자열이 코퍼스에 있는지 단위
  테스트가 검사한다. 인덱스 파일 이름을 내용 지문으로 바꿔 Railway 볼륨의 옛 인덱스가 다시 쓰이지 않게 했다.
